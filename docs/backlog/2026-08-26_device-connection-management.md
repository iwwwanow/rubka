# Менеджмент подключения между устройствами (laptop↔desktop)

Фича: менеджмент подключения между устройствами (laptop↔desktop). Сейчас
вся логика живёт в dotfiles как zsh-функции и отдельный скрипт
(`iwwwanow_dotfiles/.zshrc:58-81`, `iwwwanow_dotfiles/.local/bin/desktop-watch`)
— этот функционал целиком хочется перенести в rubka:

- `desktop()`: ssh-подключение к машине `desktop` с пробросом портов
  (фиксированный 4200 + все текущие docker-порты) и attach/create
  zellij-сессии `main` на удалённой машине
- `desktop-watch`: фоновый процесс поверх `ssh desktop "docker events ..."`
  — на каждый новый контейнер добавляет port-forward в уже открытую
  ControlMaster-сессию (`ssh -O forward`), без реконнекта и без
  перезапуска zellij; убивается вместе с завершением `desktop()`
- `desktop-fwd`: разовый ручной форвард одного порта в уже открытую сессию

Индикация подключения (например в waybar-модуль, по аналогии с
существующими custom-модулями timew/recorder) — обязательная часть,
не опционально.

Соотнести с пунктом "менеджер входа" в [[2026-07-28_modules-idea-list]] —
возможно один и тот же контур ответственности, надо будет решить на
старте сессии проработки.

## Конфигурация и ротация нод

Тот же контур: сегодняшний обрыв `desktop()` (mihomo сломал `tailscaled` на
десктопе, подробности — `iwwwanow_dotfiles/docs/backlog/2026-08-26_ru-node-fallback-for-device-connectivity.md`)
навёл на мысль, что конфигурация путей подключения (Tailscale, SSH
jump-host через РФ-ноду типа `timeweb` как фолбэк в обход mihomo) и ротация
между ними — тоже задача менеджмента подключения между устройствами, а не
что-то отдельное. То есть rubka должна не только держать/индицировать
текущее соединение (`desktop()`/`desktop-watch`), но и знать про несколько
путей и уметь между ними переключаться при отказе основного.
Не проработано — какая нода активна, как определяется отказ, ручное
переключение или авто — вопросы для отдельной сессии.

CLI-интерфейс наметился: `rubka node add` (существительное первым, глагол
вторым — по аналогии с `git remote add`/`docker network create`, дальше под
тот же `node` естественно лягут `node list`/`node remove`/`node switch`).
