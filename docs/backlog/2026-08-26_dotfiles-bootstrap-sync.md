# Синхронизация dotfiles-бутстрапа через rubka

Идея, пока размытая: синхронизацию dotfiles-бутстрапа
(`iwwwanow_dotfiles/scripts/bootstrap.sh` + `scripts/bootstrap/NN_*.sh`)
тоже подтянуть в общую систему rubka. Не проработано даже на уровне
acceptance criteria — не ясно, что именно должно синкаться (сам факт
запуска bootstrap на новой машине? дрифт между машинами? что-то ещё).
Не блокер, требует отдельной сессии на формулировку, прежде чем
превращать в фичу с конкретным скоупом. Возможно пересекается по контуру
с [[2026-08-26_device-connection-management]] (обе идеи — про
согласованность между laptop и desktop).

## Конкретная форма: `rubka device init`

Один из вариантов, куда это может вылиться — команда инициализации нового
устройства: `rubka device init`. Последовательность: pull dotfiles → pull
всех связанных репозиториев → bootstrap.

- `device init`, а не `add device` — семантически это прогон
  последовательности действий на самом устройстве, а не регистрация
  устройства в каком-то списке известных.
- вложенная группа `device` (а не плоский `init-device`), потому что вокруг
  устройства уже вырисовывается семейство операций — см.
  [[2026-08-26_device-connection-management]] (индикация подключения,
  фолбэк/ротация нод). Это будет первая вложенная CLI-группа в rubka —
  текущая конвенция (`move-window`) плоская, kebab-case, без групп; надо
  осознанно решить, закрепляем ли паттерн групп с этой фичи.
- не проработано: список "связанных репозиториев" (откуда он берётся —
  хардкод, конфиг?), идемпотентность повторного запуска на уже
  инициализированной машине, обработка конфликтов при pull.
