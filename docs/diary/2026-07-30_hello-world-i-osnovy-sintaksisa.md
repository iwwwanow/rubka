# 2026-07-30 — hello world и основы синтаксиса

- Разобрали существующий шаблон `zig init` (`build.zig`, `build.zig.zon`,
  `src/main.zig`, `src/root.zig`) построчно — договорились, что весь его
  demo-контент (add, printAnotherMessage, тесты, fuzz-тест) можно смело чистить
  под hello-world, это просто иллюстрация возможностей из шаблона.
- `zig run file.zig` vs `zig build run`: `zig run` компилирует один файл в
  обход `build.zig` целиком (виден только `std` и относительные импорты);
  `zig build run` идёт через build-граф, который резолвит именованные импорты
  (`@import("iwwwanow_rubka")` → `src/root.zig` — связь задаётся только в
  `build.zig` через `addModule`/`.imports`, не по имени файла). Раз `main.zig`
  из шаблона уже завязан на модуль — путь запуска только через
  `zig build run`.
- `root.zig` — не спец-имя для компилятора, а конвенция: "root source file"
  модуля — это то, что сам указал в `root_source_file` при `addModule`; наружу
  модуля видны только `pub`-декларации именно из этого файла.
- Разобрали error unions: `!T` без явного набора слева — inferred error set
  (компилятор выводит набор ошибок из тела функции), это НЕ то же самое, что
  `anyerror!T`. Если в теле функции нет ни одного `try`/`return error.X` —
  выведется пустой набор, и `!void` там избыточен, честный тип — просто `void`
  (пример: `printHelloWorld`, где внутри только `std.log.info`, у которого
  сигнатура без `!` вообще).
- Аллокаторы — по всей цепочке: что такое аллокация/аллокатор в принципе, чем
  отличаются стек/куча/статическая память (стек и статика размечает
  ОС/загрузчик/линкер, куча выделяется по требованию через `mmap`/`brk`, Zig
  тут просто библиотечный код поверх сисколлов, без скрытого рантайма).
  Разобрали таблицу аллокаторов из `std.heap` (Debug/GPA, testing.allocator,
  smp_allocator, ArenaAllocator, FixedBufferAllocator, page_allocator,
  c_allocator, ThreadSafeAllocator) и когда что уместно.
  Ключевой вывод про арену: `free`/`resize` на отдельный объект не работают,
  освобождение только целиком через `deinit()` (или `.reset()` для
  переиспользования чанков) — поэтому "арена на весь процесс" опасна для
  долгоживущих серверов (монотонный рост памяти на каждый запрос), но
  нормальна для `main.zig`, потому что там время жизни арены и так совпадает
  с временем жизни процесса. Для сервера — арена на каждый запрос, не на
  процесс целиком; никакого потолка компилятор не назначает (кроме
  явного размера буфера у `FixedBufferAllocator`).
- `defer` — не language-magic RAII, а явная конструкция "выполни при выходе из
  scope любым путём"; внутри `defer` нельзя `try`/`return` (нельзя менять поток
  управления наружу) — поэтому `defer stdout_writer.flush() catch {};`
  возможен, но проглатывает свою ошибку, в отличие от явного
  `try ... flush()` в конце функции, которое честно пробрасывает ошибку, но
  не сработает при раннем выходе из функции раньше.
- `flush()` на буферизованном writer'е: буфер копится в памяти, `flush`
  форсит реальный `write()`-сисколл; без вызова в конце несброшенные данные
  тихо теряются при завершении процесса.
- `std.debug.print` (всегда stderr, безусловно исполняется, ошибки
  игнорируются) vs `std.log.*` (уровни важности, scope, минимальный уровень
  настраивается на этапе компиляции через `std_options`, бэкенд подменяем) vs
  `Io.Writer` (общий низкоуровневый интерфейс "куда-то писать байты", на
  котором и `print`, и `log` построены сверху как две разные политики).
- `anytype` у `std.log.info`/`std.debug.print` — comptime generic-параметр;
  второй аргумент должен быть tuple (`.{}`, `.{"x"}`), а не голая строка,
  потому что форматирующий код внутри читает его как структуру с полями по
  числу плейсхолдеров `{}` в формат-строке. Пустой tuple обязателен даже без
  аргументов — в Zig нет optional-параметров/перегрузок, оба параметра
  сигнатуры всегда обязательны.
- Naming conventions (официальный Zig style guide, не enforced компилятором):
  типы/error-values — `TitleCase`, функции — `camelCase`, переменные/поля/
  файлы-неймспейсы — `snake_case`, файлы, экспортирующие один тип —
  `TitleCase.zig`.
- Создан `.gitignore` (`.zig-cache/`, `zig-out/`, `zig-cache/` + типовой шум
  редакторов/ОС).
