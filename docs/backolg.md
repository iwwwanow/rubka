- долгий ящик, не сейчас (зафиксировано 2026-08-07):
  - версионирование i3-ipc протокола: отдельного номера версии протокола нет,
    привязано к версии sway. Если когда-нибудь захочется подстраховаться от
    рассинхрона (обновил sway — rubka отвалилась) — запросить `GET_VERSION`
    при старте адаптера и сверить с диапазоном протестированных версий.
    Сейчас не делать: базовый набор message types не менялся годами,
    риск чисто теоретический для личного инструмента на одной машине.
  - GNOME-адаптер (для пункта "менеджер менеджеров окон + переключение
    между ними" выше): порт `WindowManagerPort.move(direction)` под это
    уже готов, но объём работы принципиально больше, чем для sway.
    - X11-сессия GNOME: другой протокол-клиент — бинарный X11 + EWMH
      (`_NET_MOVERESIZE_WINDOW`), как у `xdotool`/`wmctrl`, без адресации
      к GNOME конкретно.
    - Wayland-сессия GNOME (дефолт): напрямую снаружи никак — Wayland
      сознательно не даёт внешнему процессу двигать чужие окна. Рабочий
      путь только через свой GNOME Shell Extension (JS внутри процесса
      compositor'а, доступ к `Meta.Window`), который сам экспортирует
      D-Bus-метод — то есть по факту два отдельных проекта вместо одного
      (rubka-адаптер как D-Bus-клиент + отдельное JS-расширение,
      которое ещё и ставить/подписывать отдельно).
    Не следующий шаг — после того, как доделан sway.
